# Phase 3 畫面細部計畫（設計簡報＋任務）

日期：2026-10-28　依據：設計第 5、7、9 節；PRODUCT.md；使用者確認的主畫面版面（HANDOFF.md）；實作計畫 Phase 3。
範圍：非 AI 的完整畫面。AI 光球、課程問答、職涯推薦、截圖匯入、畢業缺口匯入畫面屬 Phase 4，本階段只留位置與入口。

## 1. 設計簡報

**工作與使用者（Operate 模式）**：政大學生在選課期前後，用手機或筆電反覆搜課、試排、比較備案，排好後到桌機官方系統登記。介面要讓人一眼看懂「我現在排了什麼、哪裡有問題、還能做什麼」，不讓設計搶走注意力。

**成果**：學生能在 375px 手機與 1280px 桌機上完成「選學期 → 搜課 → 加入 → 看到衝堂與規則提醒 → 調整 → 存成備案 → 匯出」，全程可復原，重新整理後資料還在。

**方向（已釘選，不另發想）**：外觀照設計第 7 節方向 B 的配色與字體；版面照使用者確認的主畫面。中心思想：**課表是主角，其他東西都往課表送**。三個重點時刻：
1. 加入課程時，課表上的方格直接出現並標「新」，學分數同步更新。
2. 衝堂時，衝到的兩格變珊瑚紅，提醒列寫出是哪兩門。
3. 規則提醒每則附「選課須知 114.07 版 8-x」出處，點開看原文說明。

**版面**
- 桌機（≥1024px）：頂列（Campusward、學期、搜課輸入框、非政大官方服務）→ 方案列（主方案／備案切換、＋、學分）→ 主區兩欄：左為政大節次課表（約 3/5），右為側欄（約 2/5），側欄有兩個分頁「搜課」「AI」。在頂列輸入搜課時，側欄自動切到「搜課」顯示結果與候選清單。課表下方為規則提醒列，最底為匯出與畢業缺口入口。
- 手機（<768px）：頂列縮成學期＋搜課圖示＋選單；主區改為三個分頁「課表」「搜課」「AI」，固定在底部；課表分頁用「行程檢視」（依星期由早到晚）並可切回方格；規則提醒收在課表頂端的摘要條，點開展開。
- 平板（768–1023px）：同桌機兩欄，側欄可收合。

**狀態與資料量**
- 首次使用：課表空白時，主區顯示「從搜課開始」與「匯入舊站資料」兩個入口，教學不靠彈窗。
- 搜課：115-1 約 2,800 門以上；結果分頁或虛擬捲動，先顯示 50 筆；無結果時建議放寬條件。
- 課表：一般 6–10 門，極端 20 門；方格內文字截斷但可點開。
- 提醒：0–10 則，警告在前、資訊在後。
- 錯誤：課程資料載入失敗、本機資料壞掉改用備份（顯示提示）、另一分頁更新（顯示提示並載入）。
- 復原：每次修改後 15 秒內底部出現「已〇〇 [復原]」。

**互動與一致性**
- 所有按鈕、輸入框有清楚邊框與 AA 對比；觸控目標 ≥44px；浮雕只用在課表與側欄兩張大卡片。
- 動態 150–250ms，只表達狀態（加入、移除、切換），不做開場動畫。
- 不用彈窗作為第一選擇：課程詳情在側欄內展開；確認類操作（清除資料、蓋掉自動備案）才用對話框。

**限制**：React＋Vite＋Tailwind＋daisyUI；字型以 npm 套件隨站提供（Outfit、Noto Sans TC）；不使用 inline script（相容 CSP `script-src 'self'`）；所有外部連結經引擎 `safeExternalUrl`；不出現 Open NCCU 名稱。

**待確認（實作者預設，使用者可改）**
1. 搜課結果放在右側欄「搜課」分頁（與 AI 共用側欄），而不是另開左欄。理由：保留已確認的兩欄版面，手機上自然對應成分頁。
2. 測試資料：一次性抓取 115-1 全校課程快照（實作計畫 2.1–2.3 的抓取與檢查，不含每日自動排程 2.4，使用者已決定暫緩）。

## 2. 技術選擇

| 項目 | 選擇 |
|---|---|
| 框架 | React 19、Vite、TypeScript strict |
| 樣式 | Tailwind CSS 4＋daisyUI 5，主題 token 對應設計第 7 節色票 |
| 狀態 | `useReducer` 包引擎的純函式（PlannerState、StoredData），儲存經 `StorageLike` 接 localStorage |
| 路由 | 主畫面與隱私說明頁兩頁，不引入路由套件（依路徑切換） |
| 測試 | Vitest＋Testing Library＋jsdom（元件）；Playwright＋axe（端到端與無障礙） |
| 資料 | `data/snapshots/1151/courses.json`，建置時複製到網站靜態檔，執行期以 fetch 載入 |

## 3. 任務

每個任務：先寫元件或端到端測試、看到失敗、實作、通過、提交。

- **3.0 115-1 快照**：抓取程式（課號前綴＋A–Z、達 500 筆往下切、去重、總查詢上限，網路以假 fetch 測試）；實際抓一次 115-1，記錄筆數、耗時、查詢次數；抽查 20 門與官網比對。完成：快照檔＋檢查報告。
- **3.1 骨架**：apps/web、主題 token、字型、頂列與「非政大官方服務」、版面框架（桌機兩欄、手機底部分頁）、本機儲存掛載（含備份回退與另一分頁更新提示）。完成：375／1280 截圖、axe 無違規。
- **3.2 學期與搜課**：學期選擇、搜課（關鍵字、教師、課號、開課班級、通識類別、星期、節次）、結果列表、課程詳情（官方欄位、備註分類、連結、即時向官方確認單門課）、加入候選／課表。
- **3.3 課表**：政大節次方格（桌機）、行程檢視（手機）、衝堂標示、學分、鎖定、已灌檔／已選上、非同步切換、規則提醒列（附出處）、復原提示。
- **3.4 條件與方案**：身分與資格條件（只由學生勾選）、實習空檔設定與結果、主方案／備案切換、比較、自動備案滿了的確認。
- **3.5 匯出入與隱私**：手機桌布圖、依序複製課號清單、JSON 匯出入（含舊站匯入與學期選擇）、一鍵清除本機資料、隱私說明頁。
- **3.6 驗收**：Playwright 跑「搜課→加入→衝堂→規則提醒→匯出」桌機 1280×800 與手機 375×812；axe AA；觸控目標檢查；截圖自檢兩輪；impeccable detect 與 finish review；寫 DESIGN.md。

## 4. 完成標準

- 元件測試涵蓋每個主要互動；端到端流程在兩種尺寸通過。
- axe 無 AA 違規；鍵盤可完成核心流程。
- 重新整理後資料保留；本機資料壞掉時改用備份且有提示。
- 畫面上沒有 Open NCCU 字樣（專案檢查已會擋）。
