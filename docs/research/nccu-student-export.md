# 全人系統匯出檔（exportStudentData.json）調查

日期：2026-10-28　來源：使用者本人從政大全人系統下載的匯出檔（1 份，會計系大四、無雙主修／輔系）。
原則：本文件只記錄**欄位結構與值的種類**，不含任何真實內容；原始檔不進版控。測試一律用 `packages/engine/test/fixtures/synthetic/student-export.json`（同結構、虛構內容）。

## 1. 整體結構

最外層是陣列，每個元素是一個「區塊名稱 → 內容」的物件，共 5 塊：

| 區塊 | 內容 | Campusward 是否需要 |
|---|---|---|
| 課業學習 | 學籍（主修、雙主修、輔系、年級）、歷年成績、學校的畢業審查結果（coursePlan）、總學分、排名 | **部分需要**（見第 2 節） |
| 榮譽紀錄 | 獎懲、獎學金、競賽 | 不需要 |
| 職涯發展 | 工讀與實習經歷、證照、語言 | 不需要（職涯推薦改由學生自己描述） |
| 多元學習與發展 | 活動、社團、導師（含導師信箱與分機） | 不需要 |
| 個人資料 | 生日、手機、住址、緊急聯絡人、宿舍與**室友姓名學號** | **絕對不讀** |

## 2. 需要的欄位

### 2.1 學籍 `課業學習.aboutMe`
| 欄位 | 意義 | 用途 |
|---|---|---|
| `registerMajor` | 主修學系 | 顯示、對應課程 |
| `doubleMajor`／`registerDoubleMajor` | 雙主修 | 學分上限 31（選課須知 8-1） |
| `minor1`／`minor2`／`registerMinor` | 輔系 | 學分上限 28 |
| `program`／`registerOtherProgramList` | 學程 | 學程資格條件 |
| `departmentProgramGrade` | 班級，例「某系四乙」 | 讀出年級 → 學分下限 10／12 |
| `studentIdentity` | 身分（如「臺生(一般)」） | 暫不用 |

> 本樣本雙主修、輔系、學程欄位皆為空，**填了值時的格式尚未見過**，需第二份樣本確認。

### 2.2 歷年修課 `課業學習.gradeRecordList[].GradeRecords[]`
| 欄位 | 值的種類（本樣本） | 用途 |
|---|---|---|
| `courseCode` | 9 碼課號 | 判斷「同名或前六碼相同」的重修、擋修先修是否已修 |
| `courseName` | 課名 | 同上；比對官方擋修條件「擋修初會(二)」 |
| `credit` | 字串，如 "3.0" | 學分累計 |
| `requiredOrElectiveCourse` | 必／選／群 | 顯示 |
| `remark` | 空、人文通、社會通、自然通、資訊通、「人文通、社會通」 | 通識領域累計 |
| `score` | 數字字串，或「停修」 | **只轉成「通過／未通過／停修」**，不保存分數 |
| `academicYearSemester` | 例 4 碼學期 | 修課時間 |

> 當學期課程不在成績清單中（`showTcres` 說明成績 11 月後才開放），所以「本學期正在修」要另外處理。

### 2.3 學校的畢業審查 `課業學習.coursePlan`
| 欄位 | 本樣本的寫法 | 推測意義 |
|---|---|---|
| `graduationCredit` | 數字字串 | 畢業學分 |
| `requiredPoint`／`groupPoint` | 數字字串 | 必修／群修應修學分 |
| `requiredRemark` | `[缺課名1][缺課名1]` | **還缺的必修**（課名＋數量） |
| `commonPhysical`／`commonPhysicalCount` | `[體育欠1門]`／數字 | 體育還欠幾門／應修門數 |
| `commonLanguage`／`commonLanguageCount` | 空／數字 | 語文必修（空＝推測已滿足） |
| `liberalTotal`／`liberalGeneral`／`liberalChinese`／`liberalEnglish` | 空 | 通識各類（空＝推測已滿足） |
| `programName`／`programRemark`／`groupRemark` | 空 | 學程與群修缺口 |
| `coursePlanSchyy` | 3 碼學年 | 適用的課程架構（入學年度） |
| `coursePlanTimestamp` | 8 碼日期 | 審查資料時間 |
| `課業學習.totalCredits` | 數字字串 | 已得學分 |

> 「空字串＝已滿足」是推測，只有一份樣本；缺的項目以 `[...]` 括號列出，格式需更多樣本確認。

## 3. 對三項調查的影響

### 3.1 畢業缺口檢查（計畫 2.5）——做法可以大幅簡化
- 原設計：每個學系手寫「規則檔」（必修科目表、版本、出處），本機比對修課紀錄；沒有規則檔的學系顯示「尚未支援」。最大風險是資料取得與維護（設計第 14 節）。
- 新發現：**學校的畢業審查結果已在匯出檔中**（還缺哪些必修、體育欠幾門、畢業學分）。直接讀出來，就能支援所有學系，不用逐系寫規則檔，也不用自己判斷抵免或學分互抵。
- Campusward 能多做的事：把「還缺的必修」對到**本學期快照中真的有開的課**（同課名），直接放進候選清單；把剩餘學分（畢業學分 − 已得學分）與本學期排課學分並列。
- 限制：只有學校審查過的項目；本學期修課不算進去；格式只看過一份樣本。
- **這是設計範圍內的做法改變，需使用者確認**（見交接）。

### 3.2 學生身分驗證（計畫 2.7）——匯出檔不能當驗證
- 匯出檔是一般 JSON，沒有簽章，任何人都能自己編一份，所以**不能證明是政大學生**。
- 仍以政大信箱一次性驗證碼或 Google 登入限 `@nccu.edu.tw` 為候選，維持原計畫評估。
- 附帶好處：匯入後可自動帶入年級、主修、雙主修／輔系，學生確認即可（身分條件仍由學生本人確認，符合設計 6.2）。

### 3.3 其他可用之處
- 擋修先修：官方條件「我修過中會(二)」可依修課紀錄自動判斷，不用學生逐一勾選（仍可手動改）。
- 重複修課：同名或前六碼相同且已通過的課，排課時提醒。
- 通識：依 `remark` 累計已修通識領域。

## 4. 隱私處理（實作時的硬規則）
1. **白名單讀取**：只讀第 2 節列出的欄位，其餘區塊與欄位（個人資料、宿舍、室友、導師、排名、操行、榮譽）一律不讀、不存。
2. 分數不保存，只留「通過／未通過／停修」；學號、姓名、英文名不保存。
3. 只存在使用者瀏覽器；**不送給 AI**（設計 6.3）；送 Gemini 的請求以測試斷言不含修課紀錄欄位。
4. 匯入畫面提醒：檔案含大量個資，用完請自行刪除下載檔。
5. 測試資料一律合成；學號檢查會擋下任何真實學號格式。
