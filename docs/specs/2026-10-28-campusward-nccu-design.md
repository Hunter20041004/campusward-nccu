## 1. 一句話

給政大學生用的選課、排課工具：說出需求，AI 光球直接幫你搜課、排課表、檢查衝堂與選課規則，做錯可以一鍵復原。免費、開源，目標是在 115-2 選課季有學生使用，之後由使用者與 Open NCCU 團隊討論是否合併進他們的既有功能。

## 4. 使用者與主要情境

使用者：政大大學部學生（含雙主修、輔系、學程、要排實習的學生），經學生身分驗證（第 6.3 節）。

1. 「我想補完財管雙主修必修，週五不要排課」：學生提供（或從規則檔取得）要補的課，AI 搜課、排出不衝堂且週五空堂的課表，直接套用，可一鍵復原。沒有對應規則檔時，AI 只用學生提供的清單，不從課名猜必修。
2. 自己搜課、點課加入課表，看衝堂、學分與選課規則提醒。
3. 比較幾個備案課表。
4. 問「這門課在教什麼？有沒有先修？」
5. 確認雙主修／學程還差什麼。
6. 描述職涯方向，請 AI 推薦該修的課。
7. 排好後匯出手機桌布、依順序複製課號清單（到官方選課系統批量登記）、匯出資料換裝置。

## 6. AI 光球

### 6.1 互動原則（使用者核可）
- 說出需求 → **直接執行**，不先預覽；執行後標示本次新增／移除，並顯示「已幫你加入 N 門課 [復原]」。
- 會替換主課表的大改動，執行前自動另存原課表為備案；自動備案有數量上限，最舊的不被悄悄覆蓋（滿了先提示）。
- 套用前一律通過確定性檢查：課程真實存在於官方快照、衝堂、鎖定課、實習天數、學分範圍；不合格不套用並說明原因。選課規則提醒（第 5 節）在套用後照常顯示。

### 6.2 呼叫架構（審查採納）
- **每次需求最多 1–2 次模型呼叫**：搜課、篩選、衝堂由引擎確定性完成；模型只輸出一份結構化「變更方案」（整批 add/remove），引擎驗證後一次套用，作為單一復原單位。
- AI 只能從有限動作清單選擇：搜課、開課程詳情、加入／移出候選、加入／移出課表、建立／切換備案、設定**偏好類**條件（空堂日、實習時段）、回答課程問題、職涯推薦。**不能**設定身分或資格條件。
- 錯誤分類依 Gemini 回應的 `error.details[].reason`（API_KEY_INVALID、RESOURCE_EXHAUSTED 等）判斷，不再把 400/401 一律當金鑰無效（舊程式 gemini-client.mjs 第 25–26 行的問題，**事實**）。
- 模型名稱集中在一個設定檔。

### 6.3 金鑰與身分（使用者決定）
- **使用者自帶 Gemini 金鑰**（使用者 2026-10-28 確認維持）。
- **學生身分驗證**：使用者決定以驗證學生身分處理 Gemini 條款的年齡與使用對象限制。驗證方式在實作計畫中設計（例如政大信箱驗證），需符合「不在伺服器保存使用者資料」的原則，若需要最小伺服器，於計畫中明列。
- **已知條款事實**（Gemini API Additional Terms，2026-03-23 生效，2026-10-28 讀原文）：使用者須年滿 18 歲；不得用於「directed towards or is likely to be accessed by individuals under the age of 18」的網站或應用；Gemini API 定位為「professional or business purposes, not for consumer use」；免費額度內容可能用於改進 Google 產品並可能由人工審閱，條款要求不要送出敏感或個人資料。實作時：金鑰申請說明頁明列以上條款；修課紀錄與成績不送給 AI；截圖匯入前提醒裁掉個資。
- 金鑰預設**只存在記憶體**（重新整理就要重貼，與舊版行為相同）；使用者勾選後才存 sessionStorage；提供明顯的「移除金鑰」按鈕。金鑰以請求標頭傳送，不放網址、不進匯出檔、錯誤訊息與 console。
- 沒有金鑰：非 AI 功能全部可用；AI 處顯示申請金鑰步驟與「看示範」。
- 不使用中國來源模型（沿用政大排課的供應鏈檢查）。

### 6.4 安全（審查採納）
- 課綱與網路內容視為資料，不當指令；AI 回覆中的課號一律回頭比對官方快照。
- AI 回覆**不顯示任何外部圖片**；連結只允許 https 且限白名單網域；禁止 `javascript:` 連結；不以 HTML 直接插入任何內容（lint 禁止 `dangerouslySetInnerHTML`）。
- 單次變更方案的動作數有上限。
- 品質門檻含提示注入攻擊測試題。

## 8. 架構

### 8.1 分層
```
packages/engine   TypeScript 純邏輯，不依賴畫面框架、不載入 node:*
                  政大節次、衝堂、學分、選課規則提醒、資格、實習空檔、
                  備案、復原、變更方案驗證、AI 動作定義、儲存格式與遷移
apps/web          React + Vite + Tailwind CSS + daisyUI
scripts/          建置期資料管線：全校課程快照、課綱語料與索引、規則檔
```
技術理由：React 與 daisyUI 為 Open NCCU **推測**使用的技術（vendor bundle 有 react-dom；CSS 變數為 daisyUI 命名），利於日後合併；此為使用者全域規則「預設 shadcn/ui」的明示例外。

### 8.2 課程資料（審查採納）
- **事實**（2026-10-28 實測）：`es.nccu.edu.tw/course/zh-TW/:sem=<學期> <關鍵字> /` 帶 `Access-Control-Allow-Origin: *`；寬查詢上限 500 筆、約 16–18 秒；以課號前綴查詢（例「351」）0.4 秒、可分批；`:sem=1152` 目前 0 筆，115-2 尚未公布。
- **建置期全校課程快照**：依課號前綴分批抓取、檢查筆數合理、失敗保留上一版；GitHub Actions 每日重建；每日檢查 1152 是否公布，公布即重建並通知。
- 保留官方欄位 `smtQty`、`gdeType`、`pay`、`subGde`、`subKind`、`core`、`emiType`、`lmtKind`、`subRemainUrl`（舊 adapter 只保留部分，**事實**）。
- 人工時段更正表改用「學期＋課號」為鍵，加測試確保不跨學期套用（舊表只用課號，**事實**）。
- 資料管線先在 1151 全自動跑通並寫成驗收測試。

### 8.3 部署
- **事實**（實測預檢）：Gemini API 允許瀏覽器直接呼叫（回 `access-control-allow-origin` 與允許 `x-goog-api-key`）。
- 網站為純靜態，部署在 **Cloudflare Pages**（免費；可用 `_headers` 設 CSP 等安全標頭；獨立網域，不與使用者其他 GitHub Pages 專案同源——**事實**：hunter20041004.github.io 已有 factorymind-webapp）。需使用者建立 Cloudflare 帳號。學生身分驗證若需最小伺服器，以 Cloudflare Workers 實作並於計畫中說明資料處理。
- CSP：`script-src 'self'`；`connect-src` 僅本站、`es.nccu.edu.tw`、`generativelanguage.googleapis.com`（及身分驗證所需端點）。
- 舊站 `nccu-course-planner-1151.huntertseng.chatgpt.site` 於新站上線後撤下。

### 8.4 課程問答
- **事實**：課綱主機 `newdoc.nccu.edu.tw` 不回 `Access-Control-Allow-Origin`，瀏覽器不能執行期抓課綱；單頁 HTML 約 66–138 KB。
- 課綱於**建置期**抓取：索引只收課名、簡介、目標、評分、先修、每週主題；去除教師聯絡方式；全文按課分檔、點開才載入；每段附原始網址；提供教師或學校申請移除的管道。
- 瀏覽器以中文切字（二字一組）＋BM25 找候選段落（採現成套件如 MiniSearch／FlexSearch），交給 Gemini 依段落作答並附出處。
- 量化門檻：首次載入索引壓縮後 < 3 MB、手機搜尋 < 300 ms；以 IndexedDB／Cache API 快取。
- 驗收題至少 30–50 題（含概念型），記錄召回率；不足再評估向量檢索。
- 115-2 課綱未齊全時，畫面顯示「本學期課綱尚未齊全」，可回退顯示同課號前學期課綱並註明學期。

### 8.5 畢業缺口檢查
- 修課紀錄：先支援手動輸入與貼上文字；全人系統匯出格式待第一週調查後再加上傳。
- 規則檔格式第一週定稿，附範例與測試；每條規定附來源連結與版本；首批只做資料可取得、可驗證的學系／學程。
- 輸出標示「僅供參考，以系所審核為準」，並列出未檢查的項目（抵免、學分互抵等）。
- 比對全部在本機以規則完成，不送給 AI。

### 8.6 職涯推薦
- **事實**（ai.google.dev pricing、structured-output）：免費層的 Google 搜尋只有 `gemini-2.5-flash`／`flash-lite` 可用（合計每日 500 次）；結構化輸出搭配搜尋只限 Gemini 3 系列。
- 採**兩段式**：第一段用 2.5 Flash＋Google 搜尋產生文字；第二段另一次呼叫整理成結構化結果。引文以 Gemini 搜尋回傳的來源片段比對，並依 Google 搜尋的使用規定顯示搜尋建議與來源連結。
